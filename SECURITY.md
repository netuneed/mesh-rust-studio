# Security policy

Security reports are welcome for the source preview and Windows validation packages, including the launcher, first-run profile import, shared library handling and release archives. For older versions, include the last version you reproduced the issue on.

## Report privately

Under the repository's **Security → Advisories**, choose **Report a vulnerability**. If the form is unavailable, open an issue titled "Private security contact requested" and keep reproduction details for the private channel. Reports in English or Russian are welcome. [GitHub private vulnerability reporting](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately)

Include the build or commit, Windows version, steps to reproduce, and the impact. Use a small synthetic `.blend` or a clean test profile where possible. Remove tokens, personal paths, project files and other private data from public issues and shared logs.

Report a vulnerability specific to Blender itself through the Blender project. If the issue affects both builds, mention the upstream report in your private report here. [Blender security policy](https://developer.blender.org/docs/handbook/bug_reports/vulnerability_reports/)
